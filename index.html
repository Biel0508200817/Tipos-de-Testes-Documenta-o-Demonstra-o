MÓDULO 01

Testes Unitários

Os Testes Unitários (ou Unidade) validam o menor pedaço de código testável de uma aplicação de forma isolada — tipicamente uma função, método ou classe. Eles são a base da pirâmide de testes e garantem que a lógica individual responda corretamente às entradas.

Princípios F.I.R.S.T.

  • Fast: Execução em milissegundos.
  • Independent: Sem dependências entre testes.
  • Repeatable: Mesmos resultados em qualquer ambiente.
  • Self-validating: Retorno Booleano (Pass/Fail).

Frameworks Principais

Jest (JavaScript / Node)
Suporte nativo a Mocks, Asserções e Code Coverage integrado.
JUnit 5 (Java)
Padrão da indústria para ecossistema Java com anotações avançadas (@Test, @ParameterizedTest).

                            MÓDULO 02
                        

                        

                             Testes de Integração
                        

                    

                    
                


                
                

                    

                        

                             Estratégias & Desafios
                        

                        

                            Os testes de integração verificam se múltiplos componentes (APIs, bancos de dados, serviços de terceiros, filas) trabalham em harmonia.
                        

                        
    
                            
  •  Setup & Teardown: Preparar e limpar a base de dados a cada execução.
    • 
                            
  •  Mocking de Serviços: Simular APIs externas instáveis usando stubs.
    • 
                            
  •  Contratos de API: Garantir compatibilidade de schemas JSON/XML.
    • 
                        

                    


                    

                        

                             Ferramenta: Postman
                        

                        

                            O Postman permite criar coleções de testes automatizados para endpoints HTTP, realizando validações de status, tempo de resposta e integridade da carga útil (payload).
                        

                        

                            pm.test("Status code is 200", function () {

                              pm.response.to.have.status(200);

                            });

                            MÓDULO 03
                        

                        

                             Testes de Sistema (E2E)
                        

                    

                    
                


                

                    

                        

                            Os Testes de Sistema ou End-to-End (E2E) testam o software por completo a partir do ponto de vista do usuário final, simulando interações reais em navegadores (cliques, preenchimento de formulários, navegação).
                        

                        

                            Boas Práticas de Teste E2E:
                            
    
                                
  • Usar o padrão Page Object Model (POM) para evitar duplicação de seletores.
    • 
                                
  • Evitar "sleeps" fixos; utilizar esperas explícitas / dinâmicas (Auto-waiting).
    • 
                                
  • Manter a suíte focada em jornadas críticas devido ao tempo de execução mais elevado.
    • 
                            

                        

                    


                    

                        

                             Selenium vs Playwright
                        

                        

                            

                                Selenium: Pionero na indústria, suporte multi-linguagem amplo, utiliza protocolo WebDriver.
                            

                            

                                Playwright: Ultra rápido, suporte nativo a múltiplos contextos/abas, interceptação de rede instantânea.

                            MÓDULO 04
                        

                        

                             Testes de Performance
                        

                    

                    
                


                
                

                    

                        
Tempo de Resposta (Latency)

                        
Tempo gasto entre o envio da requisição e a recepção da resposta completa. Mensurado em percentis (P90, P95, P99).

                    

                    

                        
Throughput (Vazão)

                        
Quantidade de requisições por segundo (RPS/TPS) que o servidor consegue processar de forma estável.

                    

                    

                        
Ferramenta: Apache JMeter

                        
Simula carga massiva usando Thread Groups, acionadores de tempo e relatórios detalhados de vazão e estresse.

Eliminam os problemas clássicos de waits e instabilidade.
